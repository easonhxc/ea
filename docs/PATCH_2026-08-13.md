# UniPath v2.2 — Application Strategy Persistence Fix

This patch fixes the Applications page so it remains useful even before the user manually saves colleges.

## Changes

- Loads the latest prediction run on login/refresh.
- Re-syncs saved application plan probabilities, tiers, program labels and majors whenever the college model is rerun.
- Enriches saved application plans with country and rank from the university catalog at runtime, so round validation and Top-20 simulation work without a database migration.
- Prevents duplicate saved-school rows by updating an existing school rather than inserting another copy.
- Builds a balanced 11–12 school model draft when the user has predictions but no saved schools.
- Adds **Save suggested list** to persist that draft.
- Makes ED / EA / RD strategy visible automatically on the Applications page.
- Shows ED I candidates, ED II contingency candidates, EA/REA/SCEA options, RD core, and portfolio risk shape.
- Allows Monte Carlo simulation of the current draft even before it is saved.
- Clears stale simulation results whenever the underlying application list changes.
- Stops showing misleading `0.0 / 100%` simulation metrics before a simulation has actually run.
- Renames the global `Save` action to `Save profile` to reduce confusion with saving colleges.

No Supabase schema migration is required for this patch.
